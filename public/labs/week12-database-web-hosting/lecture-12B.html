Week 12B: Git and GitHub basics

Learn how to save a project’s history on your computer and upload it to GitHub.

Download this notebook · Previous: DuckDB Spatial

Goal: create a small repository, upload a README, and make one update. Run all commands below in a terminal, one line at a time. No new Python package is needed; keep using your existing geospatial environment for Python work.

1. Register a GitHub account and install Git

  1. Go to github.com/signup and register a free GitHub account. Verify your email address. If you already have an account, sign in.
  2. Write down your GitHub username; you will use it in your repository URL.
  3. Install Git for your operating system. On Windows, use Git Bash for this exercise. Reopen your terminal after installation.
  4. Check that Git is installed:
git --version

Git records changes on your computer. GitHub is a website that stores a copy of your repository online, so you can share your work.

GitHub account setup guide.

2. How do Git and GitHub fit together?

A repository is a project folder with a history of saved changes. A commit is a saved snapshot with a message describing the change.

YOUR COMPUTER                                      GITHUB (online)

Project files     Staging area     Local history     Online repository
README.md         Changes chosen   Saved commits     Copy you can share
                  for next commit
     │                  │                │                  ▲
     └── git add ───────►│                │                  │
                        └── git commit ─►│                  │
                                         └── git push ──────┘

  git init: start a local repository
  git status: check files and staged changes
  git remote add origin: connect it to a GitHub repository URL

git add chooses changes for the next snapshot. git commit saves that snapshot locally. git push uploads your saved commits to GitHub. You can commit without being connected to the internet; pushing needs an internet connection.

3. Start a local repository: git init and git status

Inside your personal week12 folder, create a new folder named github-practice. Open a terminal inside week12/github-practice. Use a personal folder outside the downloaded course Git repository.

Create a text file named README.md in this folder using your text editor. Write:

# My Week 12 project

I am learning Git and GitHub for geospatial data science.

Start tracking this folder:

git init -b main
git status

git init creates a local repository. -b main names its first branch main. git status should list README.md as untracked: the file exists, but Git has not saved it yet.

Keep downloaded datasets in week12/data, outside this practice repository:

week12/
├── data/
│   ├── census_sample.parquet
│   └── districts_2015.geojson
├── lecture-12B.ipynb
└── github-practice/       ← run Git commands here
    └── README.md

4. Save your first snapshot: git add and git commit

Choose the file to include, then check its status:

git add README.md
git status

The file should now appear under Changes to be committed. Save the snapshot with a short message:

git commit -m 'Add my project introduction'
git status

-m supplies the commit message. Use a message that describes what you changed. After the commit, Git should report a clean working tree.

First-time setup: if Git asks who you are, run these commands with your own name and email, then run the commit command again:

git config user.name "Your Name"
git config user.email "you@example.com"

These settings identify your commits; they do not sign you into GitHub.

5. Connect to GitHub: git remote

In your browser, sign in to GitHub and create a new repository:

  1. Click + → New repository.
  2. Name it week12-practice and choose Public for this class exercise.
  3. Leave the README, .gitignore, and license options unchecked so the online repository starts empty.
  4. Click Create repository and copy its HTTPS URL.

Back in the same terminal, replace YOUR-USERNAME with your GitHub username:

git remote add origin https://github.com/YOUR-USERNAME/week12-practice.git

A remote is the address of an online repository. origin is the name we give this connection. This command connects your local repository to that address; it does not upload your files yet.

6. Upload your commits: git push

git push -u origin main

This uploads your local main branch to GitHub. -u remembers the connection so future uploads can use just git push.

Follow Git’s sign-in prompts. If HTTPS authentication asks for a password, GitHub requires a personal access token rather than your GitHub account password; follow GitHub’s authentication guide.

Refresh your repository page in the browser. You should see README.md and your commit message. Copy the repository URL to share your work.

A GitHub repository page displays your files and history. Publishing an HTML website with GitHub Pages is a separate step; this exercise ends with uploading your project.

7. Practice making an update

Add one sentence to README.md, such as “My data are stored locally in week12/data.” Save the file, then run:

git status
git add README.md
git commit -m 'Describe my local data folder'
git push

Refresh GitHub to see your change. You only need git init and git remote add origin once for this project. Repeat status → add → commit → push whenever you want to save and upload another change.

Command Purpose
git init -b main Start a repository
git status See what changed
git add README.md Choose changes for the next commit
git commit -m 'Describe the change' Save a snapshot locally
git remote add origin URL Connect to your GitHub repository
git push -u origin main Upload the first time
git push Upload later commits
