1. Turn your notebook into a report with Quarto

Where: your terminal, opened in week12.

Quarto is a publishing tool. It takes a notebook’s text, code, tables, and plots and puts them into an HTML page that people can read in a browser.

First, finish Part A and save the notebook with its outputs as week12/lecture-12A.ipynb. Then install the Quarto command-line tool for your operating system. Quarto is installed separately from Python.

Open a new terminal inside your local week12 folder:

conda activate geospatial
quarto --version
quarto render lecture-12A.ipynb --to html

What you should see: a new file named lecture-12A.html. Open it in your browser. Keep the accompanying lecture-12A_files folder next to it; it contains files the page needs.

This command uses the results already saved in your notebook. If you change the analysis, run the notebook again, save it, and repeat the render command.

Try it: add a Markdown sentence explaining one result in Part A. Save the notebook, render again, and find the sentence in the HTML report.

2. Use ChatGPT to help build a simple website

An HTML report shows your analysis. A small website can introduce the question and highlight one map or chart.

Use the Part A exports from week12/outputs, especially:

  • category_counts.json: the actual counts to display.
  • district_sample_map.png: the map to show.
  • district_counts.csv: a table readers can download.

Where: the ChatGPT app or website.

Open ChatGPT and attach these small files if your interface supports attachments. Otherwise paste the JSON and describe the other files. This exercise uses the ChatGPT interface; you do not need an API key or a new Python package.

Copy and adapt this prompt:

Help me build a simple website for my Week 12 geospatial class project.
The audience is classmates who have not seen my notebook.

Use my category_counts.json, district_counts.csv, and
district_sample_map.png files. Show a title, a short introduction,
a bar chart using the supplied counts, the map with a caption,
a link to download the CSV table, and a link to my notebook report
called lecture-12A.html in the same folder as index.html.

Explain that these are synthetic historical Census teaching dots
and 2015 district boundaries. Counts are sample dots, not population
estimates or current demographics. Do not invent values.

Return three complete files: index.html, styles.css, and app.js.
Use plain HTML, CSS, and JavaScript, with input files in assets/.
Make the page easy to read on a phone. Explain how to save and preview it.

A clear prompt says what to make, who will read it, which files to use, and what the result must include. Read the returned code and instructions before using them.

3. Save and preview the website

Where: your file manager and text editor.

Create a website folder inside your local week12 folder. Save ChatGPT’s code in files with these exact names. Copy your actual Part A exports into assets:

week12/
├── data/                     # downloaded source datasets
├── outputs/                  # results created in Part A
├── lecture-12A.ipynb
├── lecture-12A.html
├── lecture-12A_files/
└── website/
    ├── index.html
    ├── styles.css
    ├── app.js
    └── assets/
        ├── category_counts.json
        ├── district_counts.csv
        └── district_sample_map.png

Also copy your rendered lecture-12A.html and its entire lecture-12A_files folder into week12/website. Keep the two names unchanged so the report’s images and formatting continue to work. The website’s report link should point to lecture-12A.html.

Copy only the file contents, leaving out Markdown markers such as ```html. ChatGPT code blocks must be saved as files on your computer.

In a terminal inside week12/website, run:

conda activate geospatial
python -m http.server 8000 --bind 127.0.0.1

Open http://localhost:8000 in your browser. What you should see: your homepage, chart, and map. Click the CSV download link and the notebook report link to check them.

This runs a small local file server, so the page can load its JSON data. localhost means your computer; this URL is not a public website link. Press Ctrl+C in the terminal when finished.

For comparison, download the working website starter. For a later project with several pages, the Quarto website starter includes a homepage and notebook report; see Quarto’s website guide.

4. Vibe coding: describe, test, and improve

Here, vibe coding means using everyday language to ask an AI tool for code, then testing the result and asking for specific changes. You still need to check that the website works and tells the truth about your data.

Describe your goal → Get code → Save and test → Describe one change
                                      ▲                 │
                                      └─────────────────┘

Check three things before asking for improvements:

  1. Data: do the chart values match your exported JSON?
  2. Files: do the map and CSV download link work?
  3. Explanation: are the title, captions, and sample-data limitations clear?

Ask for one change at a time. For example:

The page opens, but the chart is empty. The browser's Network tab shows
404 for category_counts.json. My file is in assets/category_counts.json.
Please fix the file path and explain the change.

Or:

The page works. Please make the text larger and place the map below
the chart on phones. Preserve the data values and captions.

Try it: request one improvement, save the updated files, refresh the browser, and check that the data and map still work.

5. Register a GitHub account and install Git

  1. Go to github.com/signup and register a free GitHub account. Verify your email address. If you already have an account, sign in.
  2. Write down your GitHub username; you will use it in your repository URL.
  3. Install Git for your operating system. On Windows, use Git Bash for this exercise. Reopen your terminal after installation.
  4. Check that Git is installed:
git --version

Git records changes on your computer. GitHub is a website that stores a copy of your repository online, so you can share your work.

6. How do Git and GitHub fit together?

A repository is a project folder with a history of saved changes. A commit is a saved snapshot with a message describing the change.

YOUR COMPUTER                                      GITHUB (online)

Project files     Staging area     Local history     Online repository
README.md         Changes chosen   Saved commits     Copy you can share
                  for next commit
     │                  │                │                  ▲
     └── git add ───────►│                │                  │
                        └── git commit ─►│                  │
                                         └── git push ──────┘

  git init: start a local repository
  git status: check files and staged changes
  git remote add origin: connect it to a GitHub repository URL

git add chooses changes for the next snapshot. git commit saves that snapshot locally. git push uploads your saved commits to GitHub. You can commit without being connected to the internet; pushing needs an internet connection.

7. Track your website: git init and git status

Where: a terminal opened inside week12/website, the folder containing index.html. Keep your personal week12 folder outside the downloaded course Git repository.

Create a text file named README.md in this folder using your text editor. Write:

# My Week 12 project

I am learning Git and GitHub for geospatial data science.

Start tracking this folder:

git init -b main
git status

git init creates a local repository. -b main names its first branch main. git status should list README.md as untracked: the file exists, but Git has not saved it yet.

Keep downloaded source datasets in week12/data, outside the website repository. Only the small results used by your page belong in website/assets.

What you should see: git status lists your website files, the report, and README as untracked. Nothing has been uploaded yet.

8. Save your first snapshot: git add and git commit

Choose all files in this website folder, then check their status:

git add .
git status

The files should now appear under Changes to be committed. Save the snapshot with a short message:

git commit -m 'Add my website and notebook report'
git status

The dot in git add . means “include changes in this folder and its subfolders.” Run it from week12/website.

-m supplies the commit message. Use a message that describes what you changed. After the commit, Git should report a clean working tree.

First-time setup: if Git asks who you are, run these commands with your own name and email, then run the commit command again:

git config user.name "Your Name"
git config user.email "you@example.com"

These settings identify your commits; they do not sign you into GitHub.

9. Connect to GitHub: git remote

In your browser, sign in to GitHub and create a new repository:

  1. Click + → New repository.
  2. Name it week12-website and choose Public for this class exercise.
  3. Leave the README, .gitignore, and license options unchecked so the online repository starts empty.
  4. Click Create repository and copy its HTTPS URL.

Back in the same terminal, replace YOUR-USERNAME with your GitHub username:

git remote add origin https://github.com/YOUR-USERNAME/week12-website.git

A remote is the address of an online repository. origin is the name we give this connection. This command connects your local repository to that address; it does not upload your files yet.

10. Upload your commits: git push

git push -u origin main

This uploads your local main branch to GitHub. -u remembers the connection so future uploads can use just git push.

Follow Git’s sign-in prompts. If HTTPS authentication asks for a password, GitHub requires a personal access token rather than your GitHub account password; follow GitHub’s authentication guide.

Refresh your repository page in the browser. You should see README.md and your commit message. Copy the repository URL to share your work.

A GitHub repository page displays your files and history. Publishing an HTML website with GitHub Pages is a separate step; this exercise ends with uploading your project.

11. Practice making an update

Change one sentence on your homepage (index.html) or in README.md. Save the file, then run:

git status
git add .
git commit -m 'Improve my website introduction'
git push

Refresh GitHub to see your change. You only need git init and git remote add origin once for this project. Repeat status → add → commit → push whenever you want to save and upload another change.

Command Purpose
git init -b main Start a repository
git status See what changed
git add . Choose the website changes for the next commit
git commit -m 'Describe the change' Save a snapshot locally
git remote add origin URL Connect to your GitHub repository
git push -u origin main Upload the first time
git push Upload later commits

12. Publish your website with GitHub Pages

Where: your repository page on GitHub, in your browser.

Your files are now on GitHub. Turn on GitHub Pages so visitors see the website:

  1. Open your week12-website repository.
  2. Click Settings → Pages.
  3. Under Build and deployment, select Deploy from a branch.
  4. Select main and /(root), then click Save. We use the root because index.html is at the top of your website repository.
  5. Wait for the deployment to finish. Open the website link shown on this settings page.

Your two links serve different purposes:

Link What people see
https://github.com/YOUR-USERNAME/week12-website Project files and saved commits
https://YOUR-USERNAME.github.io/week12-website/ The published website

What you should see: the same homepage you tested at localhost. Check the map, chart, CSV link, and report link again. Use relative links such as assets/category_counts.json, without a leading slash.

GitHub Pages serves HTML, CSS, JavaScript, and saved outputs. It does not run your Python notebook or DuckDB queries. Keep the source datasets in your local week12/data folder.
